§1 AgentOS：为什么所有云端免费模型都不可用

1.1 现象（实测复现）

经 http://127.0.0.1:8011 向免费池发问，返回一句话而非模型作答：

POST /v1/chat/completions  {"model":"free/auto"}
→ "所有云端免费 API 暂不可用，请稍后重试，
   或改用 #local（本地模型）/ #ceo（付费模型）模式。"

该话术出处已定位到 main.py 第 1543 / 1576 行 —— 是网关全部候选端点尝试失败后的兜底文案。用户看到的"不可用"＝免费池 14 个端点无一能成功应答。

一个易被误判的细节：网关返回体里 usage 恒为 0/0/0，那是 _make_usage_placeholder() 造的占位符，不代表上游没返回 token。判断真伪要看 choices[0].message.content。

1.2 根因 A · 供给层 FreeLLMAPI 从未启动（一行路径写错）

网关注册表把 freellmapi-pool 定为免费池首选候选（reliable=10 最高权重、并发 8、号称 358 端点），指向 http://127.0.0.1:3001/v1。但该端口根本没有监听。

守护脚本 supervise_freellmapi.py 每 30 秒探活一次、失败就重启，而日志里是无限循环的同一行失败：

[2026-09-14 21:51:16] supervisor: :3001 down -> restarting FreeLLMAPI
[2026-09-14 21:51:16] supervisor ERROR: [WinError 2] 系统找不到指定的文件。

对照源码，病因是一行硬编码：

# supervise_freellmapi.py 第 6 行
NODE = r"C:/Users/oran/.workbuddy/binaries/node/versions/22.22.2-2/node.exe"
# 本机实际存在：versions/  22.22.2-3   ← 仅此一个

结论：22.22.2-2 这个 Node 版本在本机不存在，subprocess.Popen 抛 WinError 2，于是守护进程每 30 秒空转一次，FreeLLMAPI 自 9-01 集成以来一天都没真正跑起来过。网关侧对应表现：freellmapi-pool available=false、consecutive_failures = 72。

1.3 根因 B · 直连池被 429 打空，只剩 1 家苟活

供给层缺席后，全部压力落到 12 个直连端点上。网关日志（21:33–21:54 窗口）给出实况：

Provider端点日志实况判定
openrouter10 个免费模型HTTP 429 限流（反复触发）额度耗尽
agnesagnes-2.0/2.5-flashHTTP 429 + ReadTimeout额度耗尽
nvidiaopenai/gpt-oss-20b ×2唯一能命中；但 ReadTimeout 频发勉强可用
freellmapi358 端点聚合:3001 无监听（见根因 A）完全缺席

这解释了一个"时好时坏"的迷惑现象：极短请求能答对（1+1→2、复述随机串都成功，因为 nvidia 接住了），稍长的生成必挂（nvidia 只有 2 个端点、ReadTimeout 直接击穿候选链）。

1.4 根因 C · 架构放大器：一个端点 429，整组陪葬

free_api_router.py 的降级粒度是 provider 级，不是端点级：

# main.py 1316-1319
if kind in ("rate_limit", "block"):
    free_router.mark_provider_degraded(prov, reason)   # 整组冷却 180s

# free_api_router.py 417-420
self.provider_degraded_until[provider] = time.time() + _TUN["provider_cooldown_seconds"]

后果：OpenRouter 只要任意一个模型撞上 429，其余 9 个模型连同冷却 180 秒。本来分散的额度被"连坐"归零，把局部故障放大成全局不可用。这是"所有免费模型都不可用"被强化的直接机制。

1.5 根因 D · 假可用：健康检测永远绿灯

网关 /free/status 面板显示 14 个端点 available: true，与用户实际体感完全背离。原因是探活只打 GET /v1/models：

# free_api_router.py 344-363  _ping_api()
resp = await client.get(f"{status.base_url}/models", ...)
if resp.status_code == 200:  return True, elapsed   # 只验 key，不验生成

/v1/models 只要 API key 有效就返回 200，与"额度是否够、能否真正生成"无关。于是状态面板全绿、实际调用全挂，问题被掩埋了整整两周。
