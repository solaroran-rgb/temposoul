## 五、三处硬冲突（必须老板裁决）

### 冲突 1 —— 介质冲突（最严重）

| 项 | 内容 |
|---|---|
| 规范 §12 红线 | ❌ 回归 AI 猜图/生图静态方案 |
| 交接卡 §九 红线 | 概念图不可上线，**正式落地走 WebGL** |
| 我本轮做的事 | **把 AI 概念图资产化贴进页面** = 红线原文所指的那件事 |

### 冲突 2 —— 能力冲突（技术性出局）

老板 09-14 新 Brief 要求：**「以用户登录 IP 为定位，展示周边 30 公里范围内的真实街景」** + **「能量场连线（人—环境—宇宙的规律性影响）」**。

- 这两项的本质是 **每用户实时数据驱动** —— 每个 IP 不同，画面就不同。
- 位图烘焙是**一次性离线产物**，物理上**无法**随用户 IP 变化。
- → **即使红线放开，我的方案也满足不了老板自己提的核心需求。**

### 冲突 3 —— 目标冲突

| 项 | 内容 |
|---|---|
| 老板 09-14 指令 | 「真实首页页面**必须和效果图保持百分之百一致**」 |
| 规范 §7 已裁定 | 「**1:1 复刻**参考海报在实时 WebGL 首屏**不现实也不该做**……可达目标 = **风格同源自洽**」 |
| → | 这两条**互斥**：前者要求 100% 像素一致，后者明文放弃 1:1。这正是我上一轮"物理互斥"结论的项目版本，但**项目早已裁决过，我没去读** |

## 七、判定汇总

| 问题 | 判定 |
|---|---|
| 与 AI 地图记载的技术栈是否一致？ | **不一致** |
| 是否方向性冲突？ | **是 —— 正面对撞** |
| 是否命中明文红线？ | **是（§12 + 交接卡 §九，两处独立）** |
| 我本轮的交付可否直接上线？ | **不可以**（且不是技术问题，是路线问题） |
| 我本轮的技术产出是否全无价值？ | **不是** —— 见下 |

**本轮产出真正的可用价值（去掉违禁部分后）：**

1. **半像素陷阱**（`translate(-50%,-50%)` + 奇数尺寸 → 整层重采样）—— 这是**通用工程 bug**，与介质无关，对 WebGL 版的 UI 层同样适用。
2. **内容门禁**（`h1Count` / `body.innerText` / `selectable` / SEO 元数据）—— 验收纪律，**应当并入规范 §12**。
3. **AVIF 能力探测陷阱**（`canvas.toDataURL('image/avif')` 恒返 png）—— 通用前端知识。
4. **资产化为"视觉基准归档 / OG 图 / 分享图"** —— 用途降级后仍然正确：**不是页面**，是素材。

## 八、建议（三案）

| 案 | 内容 | 代价 |
|---|---|---|
| **甲 · 合红线回归 WebGL** | 承认本轮线路违禁、作废其"页面实现"定位；把"与效果图一致"落到规范 §11 的五批整改（R1–R13 + V1–V31） | 需重走 WebGL 施工；但**已有全部基建**（真实星表/geoEngine/城市库/shaders） |
| **乙 · 正式改红线** | 若老板认为"100% 视觉一致"优先级高于"实时真实数据"，则**须正式修订 §12 红线**，并回答：L3 数据层（IP 真实城市）与"能量场连线"怎么办 | 违反规范 §7 既有裁定；丧失 IP 个性化能力 |
| **丙 · 分工（我推荐）** | **页面本体回 WebGL（案甲）**；本轮资产化产物**降级为"视觉基准图 / OG 分享图 / 保真度对照基准"**（不承担页面） | 两案优点兼得，且**不违红线** |

> **我的建议：案甲 + 案丙。** 即：资产化不做页面，只做素材；页面本体回到 WebGL 主线。理由：① 不违红线 ② 保住 IP 真实街景与能量连线这两个老板自己提的核心需求 ③ 本轮的真发现（半像素 / 内容门禁 / AVIF 探测）全部可平移到 WebGL 版。
