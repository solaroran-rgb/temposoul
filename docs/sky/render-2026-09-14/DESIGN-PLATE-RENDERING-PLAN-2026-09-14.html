02根因：为什么程序化复刻的天花板只有 40%

先把前提证伪。我们抓了线上真机 temposoul.com/sky，与 CT-1 效果图、我做的预览三方对比， 用同一套像素测法量化：

指标CT-1 效果图线上真机 /sky程序化预览
地貌细节密度7.096.52 3.13（目标 44%）
天空细节密度1.503.42 1.62
色彩丰富度238461 243

结论有三层，每一层都指向同一个答案：

第一层
CT-1 是 AI 插画
元素量级 10³–10⁴（星云颗团、多层山脊、密集塔楼）。这是静态高密度插画， 不是实时几何能自然涌现的密度。
第二层
真机同样不一致
线上真机 /sky 是实时星空观测器（5044 星 + 566 星座线 + HUD）， 它和效果图也完全不同。规范 §7 早就写明"1:1 复刻不现实"。
第三层
调参救不回来
我做了 7 轮补丁（质感三档 + 密度升级 + 定点打磨）， 把细节密度从 3.13 提到 6.48（91%）—— 但观感仍是"线稿"，不是那张图。
关键判断：问题不在"够不够密"，在"介质不同"

程序化绘制是矢量叠加，AI 插画是位图肌理。 前者画得再密，也补不出后者的体积光、大气衰减、油画笔触。 要让首页等于效果图，唯一稳的路是——直接装载效果图本身。

03方案：设计稿资产化渲染（DPR）

思路一句话：网页不再"重画"这张图，而是"装载"这张图，然后在它上面做真实数据与交互。

L0 资产层设计稿底图 CT-1 直接转为多分辨率无损 WebP / AVIF 资产。这一层决定保真度，是 100% 的来源。
L1 场景层UI 剥离版 把标题 / 副标题 / CTA 从底图抠除（区域外修改量 = 0），供自定义排版使用。
L2 动态层实时微光 可选：星点微闪、地平线呼吸、人形光环。加法混合，不破坏底图结构。
L3 数据层真实数据 可选：IP 定位城市天际线。城市带高频能量是天空带的 3.65 倍，频率域上可独立分离。
L4 UI 层HTML 排版 标题 / 副标题 / CTA 用 HTML + CSS 渲染，按设计稿实测几何定位，响应式不裁字。

三层保真语义（关键设计）

L0 与 L4 是互斥可切换的，这正是"既能 100%、又能响应式"的关键：

模式组成保真度适用
标准 F100L0 底图（含文字） 逐像素 100%桌面宽带、验收、门禁
实时 F99L0 + L2 微光 视觉无损需要呼吸感的展示页
自适应 RESPL1 场景层 + L4 HTML UI 排版级 100%（位置/尺寸/颜色实测复刻）移动端、非标准比例
数据 IPL0 + L3 真实城市 构成级一致IP 定位首页（产品功能）
为什么必须分这两条路（这是无法回避的物理事实）

设计稿是 1.981:1 的横版。手机竖屏是 0.462:1，两者相差 4.3 倍。 如果强行用同一张横版图去铺竖屏，必然裁掉 77% 的画面宽度，标题右侧会被切掉（实测：CTA 与标题的 "l" 被裁）。 所以：

  • 比例匹配时（桌面/平板，AR ≥ 1.4）→ 用含文字底图，逐像素 100%。
  • 比例不匹配时（竖屏）→ 用无文字场景层 + HTML UI，排版完整、位置尺寸按设计稿实测复刻。

06移动端：排版问题的真实解

您点名的"布局、排版、比例"三项，在桌面端已经稳定；移动端原本是崩的，这是本轮新发现并解决的真问题。

6.1 问题：横版设计稿铺竖屏必然裁字

实测：390×844 竖屏下，横版图按 cover 铺满需放大到 1672×844，水平方向裁掉 77%。 后果是标题「命律 TempoSoul」右侧的 "l" 与 CTA 边缘被切掉。

6.2 解：场景层 + HTML UI（几何按设计稿实测复刻）

从 CT-1 中把标题、副标题、CTA 精确抠除（区域外修改量 = 0， 即只动了文字区），得到"纯场景层"；文字改用 HTML + CSS 渲染，几何全部取实测值：

场景层 + HTML UI 方案下，场景部分保真度极高（辉光带差 0.114%、地形差 0.412%）， 但文字区与设计稿有字形差异（HTML 矢量字体 vs 设计稿位图文字，实测该区均差 4.70）。 所以：要逐像素 100% 就用含文字底图（桌面）；要响应式排版就用 HTML UI（移动）。 两者不能在同一张图上同时成立，这是设计稿是横版位图这一前提决定的。

07生产实施：五步落地

STEP 1出图 AI 生成设计稿（当前已有 CT-1）。未来各地/各季节版本走同一流程，一张稿对应一套资产。
STEP 2资产化 make_assets_avif.py 一键产出五档 × 双格式；remove_text.py 产出场景层。全程无人工。
STEP 3门禁 gate_compare.py 像素对拍。严格档必须 PSNR=∞ 且完全一致 100%，否则禁止上线。
STEP 4部署 home-prod-auto.html + assets/ 静态托管（CDN + HTTP/2 + 长效强缓存 + Brotli）。
STEP 5监控 页面内置 window.__PERF 埋点（首帧/档位/格式/网络），可直采上报。上线即可观测真实用户档位分布。
