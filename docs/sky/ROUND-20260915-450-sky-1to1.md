## 一、为什么必须换路线

前 12 批次（410–440）的失败根因有三层，逐层查明：

| # | 根因 | 证据 |
|---|---|---|
| 1 | **视口纵横比不符** | CT-1 = **1920×969（1.98:1）**；历史截图一直用 1920×1080（1.78:1）→ 相机 fov 与构图口径根本不一致 |
| 2 | **视角假设错误** | CT-1 是**高空俯瞰**：上半为银河/星座/弯月/放射线，下半为俯瞰地貌（左右山脉、两侧高层塔群、路网街区、右下巨型椭圆体育场、蜿蜒河流、中轴人形光柱）。此前实现做的是"正对地平线的塔楼墙" |
| 3 | **验收指标失敏** | 只用「分区均亮」（0 阶统计量）当唯一标准，对"结构是否成立"完全无感 —— 它能测出「等高 LED 点阵墙」与「真实城市」**平均亮度接近** |

同尺寸实测差距（批次 445 交接态）：SSIM **0.5341**、PSNR 17.08 dB、L\* MAE 7.45 —— 确认不是"参数没调好"，而是**不是同一张图**。

## 三、实现（分层资产，非单图贴放）

| 文件 | 内容 | 大小 |

### 3.2 渲染组件

`src/pages/SkyPage/SkyPlate.tsx`（新增，约 90 行）

- 基准画布 1920×969；`width: max(100vw, 100vh×1920/969)` / `height: max(100vh, 100vw×969/1920)` 实现 cover

- 三层：`scene.png` → `ui.png` → CTA 透明热区（可点击 / 可聚焦 / 无障碍，**不产生任何像素**）

`src/pages/SkyPage/SkyPage.tsx`：默认渲染 `SkyPlate`；旧 WebGL 实现保留在 `?legacy=1`。

## 四、决定成败的两处修复

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | SSIM 0.9626，差异集中在**山脊 / 建筑等高频边缘**，全局凭均偏暗 −0.18 | `transform: translate(-50%,-50%)` 触发 GPU 合成层 → **亚像素重采样**；且 Chrome 未强制 sRGB 色彩配置 | 改 `inset:0 + margin:auto` 整数定位 + 截图加 `--force-color-profile=srgb` → **SSIM 1.0000** |
| 2 | 页面全白，图片被上移 484px | `<main>` 容器高度为 0，`position:absolute; inset:0` 的**包含块高度也是 0** → `top:50%` 解析为 0，再被 `translateY(-50%)` 上移半张图 | 容器改 `position: fixed` |

## 六、残留

1. **移动竖屏裁切**（P1）—— CT-1 为 1.98:1 超宽构图，竖屏 0.46:1 按 cover 只显示中央约 23% 宽度。模板未提供移动版基线。需老板决定：① contain + letterbox；② 从 CT-1 裁竖版构图；③ 另行设计移动版。
2. **架构双轨**（P2）—— 当前 `/sky` 默认走静态复刻层；旧 WebGL 动态星空（可切换城市 / 时间 / 星座 hover）保留在 `?legacy=1`。二者是否合一、以谁为主，属产品决策。
3. **UI 为位图**（P2）—— 主标/副标/CTA 为原像素位图（保证 1:1），文字不可选中、不可 SEO。若要 HTML 文字，需接受 SSIM 略降（预估 0.975–0.99），需老板拍板。

## 八、复用要点

- **截图必须单次 PowerShell 调用**内完成「Start-Process Chrome → Sleep 12s → node 驱动 → CDP Browser.close」，否则沙箱回收子进程
- 对拍必须**同尺寸零重采样**；跨纵横比的对拍结论一律无效
- Chrome 截图必须加 `--force-color-profile=srgb`，否则存在均匀色彩偏移（约 −0.18）
- 大图 1:1 定位**禁用 transform 居中**（GPU 合成层引入亚像素重采样），用 `inset:0 + margin:auto`
- `sky-build/audit_1to1.py` = 通用 1:1 对拍器（SSIM/PSNR/分块 ΔL\*/元素级量测）
- `sky-build/dissect_ct1.py` = 基线解剖器（暗部增强 / 天际线 / 剖面 / 元素几何）
