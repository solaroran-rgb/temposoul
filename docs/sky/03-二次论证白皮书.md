## 1. 本地环境硬约束（专家不知道的事实）

1. **技术栈实测**：React 19.1 + Vite 7.1 + pnpm workspace；`package.json` 无 three / gsap / framer-motion / fuse.js。
2. **现有代码**：`src/lib/sky/` 是 Canvas 2D 版（astro.ts/stars.ts/SkyCanvas.tsx），`/sky` 路由已通，当前铺静态图。
3. **部署**：Cloudflare Pages，git push 部署；**无 Lighthouse CI / 无 perf-probe 基建**。
4. **网络现实**：服务器在海外 CF 节点，国内用户 RTT 偏高；Overpass API 在国内访问不稳定。
5. **预算**：CF Pages 免费层（KV 10 万次/天、1GB），不投入付费套餐。
6. **包体红线**：SkyPage 路由懒加载，主站首屏不受影响；SkyPage 自身 gzip 接受 ~200KB。

## 2. 分专家审计

### 2.1 CELESTIAL（DeepSeek · 天体）审计

**采纳**：
- 星表内联进 chunk（不 fetch .bin）——正确，省一个 RTT。
- 坐标链路 J2000→岁差→赤道→地平→天球笛卡尔——正确。
- 月亮 Meeus 简化公式 + 32 档 Canvas 贴图——可行。
- shader 星点大小/颜色/闪烁——可行。

**需修正**：
- ⚠️ 他说"BSC5 mag≤5.5 约 3000 颗"——**我们没有 BSC5 原始文件**。改用 d3-celestial 的 `stars.6.json`（MIT，公开 CDN 可下载），写一次性脚本 `scripts/gen-stars.mjs` 转成 Float32Array。
- ⚠️ 星座线数据同理，用 d3-celestial `constellations.lines.json`，不找 Stellarium GPL 数据（避免许可证污染）。
- ⚠️ 他说"星表内联无占位星空"——对，采纳。200 颗随机占位星的方案（IMMERSIVE 提的）**砍掉**，因为星表才 15KB gzip，不需要占位。
- ⚠️ 现有 `astro.ts` 已有 JD/恒星时/地平，**复用并补岁差矩阵**，不重写。

**工作量修正**：原估 2 天 → 1.5 天（复用现有 astro.ts）。

### 2.2 URBAN（通义 · 城市线稿）审计

**采纳**：
- 双阶段：0-2s 本地占位 + 2s 后异步生长——核心正确。
- 他自己修正了 Overpass 半径 20km→2km——**采纳**，原 20km 必超时。
- ENU 本地坐标系、CELL 量化、morphTo 接口——设计合理。
- 失败兜底：Overpass 挂了占位常驻，不报错——正确。

**需修正/风险**：
- ⚠️ **最大风险：OSM 中国城市建筑数据稀疏**。国内建筑轮廓主要在高德/百度，OSM 的 building way 在小县城可能几乎为空。济南这种大城市有，但边缘会缺。**接受**：占位城市保证"有城市感"，真实数据是加分项不是必需。
- ⚠️ **Overpass 回源延迟**：CF Function（海外节点）调 Overpass（德国/美国服务器），往返可能 2-4s。**修正**：不追求秒级，冷城市首访就接受占位；命中 KV <200ms。
- ⚠️ `functions/api/geo.js` 目录项目里还没有，需新建。这是 CF Pages Functions，部署自动生效。
- ⚠️ KV 命名空间需在 CF Dashboard 创建（一次性手动操作），代码里不能自动建。
- ⚠️ 建筑高度 OSM 没有就按 footprint 面积伪随机——采纳。

**工作量修正**：2.5 天（含 CF Function 调试）。

### 2.3 REALTIME（智谱 · 实时图形）审计

**采纳**（这份方案质量最高）：
- 全场景合并 geometry，≤10 draw calls——必须，否则移动端卡死。
- GPU shader 生长动画（aDelay + uGrowTime）——比 CPU lerp 优雅，采纳。
- 三态渲染状态机（GROW/AMBIENT/IDLE）——解决"微闪 vs 不重绘"矛盾，采纳。
- modulepreload sky chunk——Vite 支持，采纳。
- 画质分级 high/mid/low + deviceMemory 探测——采纳。
- 他指出 URBAN 的 stagger 0.02s×300=6s 数学错误——正确，改 GPU 波纹式。

**需修正/砍除**：
- ⚠️ perf-probe 脚本 + Lighthouse CI 卡口——**过度工程，砍**。我们没这套基建，用浏览器 DevTools 手动测一次即可。
- ⚠️ 他说"固定 three 版本"——直接 `pnpm add three@latest`，不纠结。
- ⚠️ 不引入 WebGPU / OffscreenCanvas / Line2——他的判断正确，维持。

**工作量修正**：1.5 天（砍 CI 部分）。

### 2.4 IMMERSIVE（Qwen · 视觉交互）审计

**采纳**：
- 设计 token 集中化（`src/theme/immersive.ts`）——好。
- 三阶段动效时间轴、右侧滑入面板、防抖+AbortController——合理。
- 移动端竖屏地平线 65%——合理。

**需修正**：
- ⚠️ **framer-motion / GSAP**——砍掉。项目没装，CSS transition + 少量 rAF 足够，不为这个加 50KB。
- ⚠️ **fuse.js**——砍掉。300 个城市用原生 `Array.filter` 按拼音/汉字 includes 即可，零依赖。
- ⚠️ **"人物加速旋转 0.5s"**——和用户要的"静静仰望星空"不符，改成人物轻微呼吸光效，不旋转。
- ⚠️ 城市 300 个 JSON 数据——需要准备（一次性，济南/北京/上海/省会/地级市，含 lat/lon）。

**工作量修正**：1 天。

## 3. 跨专家矛盾的主审裁定

| 矛盾 | 裁定 |
|---|---|
| 星空要不要占位（CELESTIAL 说不要，IMMERSIVE 说要 200 颗） | **不要占位**，星表内联首帧即真实 |
| 生长 stagger 间隔（URBAN 说 0.02s，REALTIME 指出=6s） | **GPU shader 波纹式**，采纳 REALTIME |
| 动效用什么驱动（IMMERSIVE 说 GSAP） | **CSS transition + 原生 rAF**，不装 GSAP |
| 城市搜索（IMMERSIVE 说 fuse.js） | **原生 filter**，不装 fuse.js |
| 2 秒验收口径 | **占位画面第一帧**（网格+占位建筑+真实星空），不含 OSM 真实街景 |
