## 1. 专家一：CELESTIAL（天体可视化）交付任务

**你负责纯算法与数据，不碰 React/Three 场景装配。**

### 必须交付的文件

| 文件 | 内容 | 验收 |
|---|---|---|
| `scripts/gen-stars.mjs` | 一次性脚本：从 jsdelivr CDN 下载 d3-celestial stars.6.json + constellations.lines.json，裁剪、转 Float32Array，产出 `src/lib/sky/stars.data.ts` 和 `constellations.data.ts` | 脚本能跑通；STAR_COUNT 4500-5500；gzip <25KB |
| `src/lib/sky/stars.data.ts` | 生成产物：`export const STAR_COUNT, STAR_DATA: Float32Array`（ra/dec 单位 rad，mag，bv） | 不要手改 |
| `src/lib/sky/constellations.data.ts` | 生成产物：`export const CONSTELLATION_SEGMENTS: [ra,dec,ra,dec][]`（度） | <400 段 |
| `src/lib/sky/astro.ts` 增量 | **在现有文件上补**：`precessionMatrix(jd)`（补全，不要省略）、`applyPrecession()`、`radecToAltAz()`、`altAzToVec3(R=500)`、LST 补经度 | 现有 toJulianDay/localSiderealTime 保留 |
| `src/lib/sky/moon.ts` | Meeus 简化轨道：太阳黄经、月球黄经黄纬→地平坐标；相位角；`makeMoonTextures()` 返回 32 档 CanvasTexture | 月相误差<5% |
| `src/lib/sky/shaders/star.vert` + `star.frag` | 星点 shader（你二次稿里的版本，attribute: position/aMag/aCi；uniform: uMagLimit/uDpr/uTime） | GLSL1 语法 |

### 接口契约（给 REALTIME）
- 星数据布局：interleaved Float32Array，每星 `[ra, dec, mag, ci]`
- shader uniform：`uMagLimit`（桌面5.5/移动4.5）、`uDpr`、`uTime`
- 星座线原始 RA/Dec（度），运行时走地平转换，不做岁差
- 月相：12 档（不是32，省贴图）CanvasTexture + 相位角函数

### 不许做
- 不写 Three.js 场景装配（那是 REALTIME）
- 不碰 React 组件
- 不引入新依赖

## 2. 专家二：URBAN（城市线稿）交付任务

**你负责城市数据管线与占位/真实几何，不碰星点和 UI。**

### 必须交付的文件

| 文件 | 内容 | 验收 |
|---|---|---|
| `src/lib/city/seed.ts` | xmur3(cityName)→mulberry32 PRNG | 同名 seed 同结果 |
| `src/lib/city/projection.ts` | `latlonToENU()`，METERS_PER_UNIT=10，正北=-z | 对齐 CELESTIAL 坐标系 |
| `src/lib/city/placeholder.ts` | `buildPlaceholderCity(seed, mobile)` → THREE.Group；30 建筑线框+1-2河+噪声地形；≤16ms | 首帧不卡 |
| `src/lib/city/config.ts` | HYBRID 阈值（FULL≥150/HYBRID 20-149/PLACEHOLDER+<20） | 单点可调 |
| `src/lib/city/geoApi.ts` | `fetchCityGeo(lat,lon,signal)` 调 `/api/geo`，带 AbortController | 失败返回 fallback |
| `src/lib/city/meshBuilder.ts` | `cityGeoToBatches(geo, mode, mobile)` → 含 position/aPosTarget/aDelay/aMatch attribute 的 BufferGeometry；≤9 draw calls | GPU 生长兼容 |
| `functions/api/geo.ts` | CF Function：KV→Overpass 三镜像轮询→简化→写 KV；永远返回 200 | wrangler 自测通过 |
| `public/data/cities.json` | 手选下拉用，~150 主要城市：`[{n, py, lat, lon, prov}]`，py 全拼小写。**不是数据来源**，只供 UI 下拉快捷选 | filter 搜"jinan"/"济南"都中 |

### 数据策略（重要修正）
- **不建全球城市库**。数据流：IP 坐标（CF request.cf）→ Overpass 实时拉 2km → KV 按坐标自动缓存（访问过才存）。
- cities.json 只是"切换时空"面板的手选下拉，可砍到 100 个主要城市，不影响新城市渲染。
- 国外城市 OSM 数据比国内小县城全，走同一管线；国内小县城走 HYBRID/PLACEHOLDER+ 兜底。

### 接口契约（给 REALTIME）
- CityBatch 含 attribute：`aDelay`（扇区0-0.5s+距中心0-0.4s）、`aTargetH`、`aMatch`(0占位/1匹配/2新增)
- HYBRID 模式 aDelay 全 0
- 切城市必须 dispose() 旧 geometry

### 不许做
- 不写生长动画 shader（REALTIME 负责）
- 不碰星空
- 不写 CF Dashboard 操作（KV namespace 创建是主审手动做）

## 3. 专家三：REALTIME（实时图形）交付任务

**你负责 Three.js 场景、渲染循环、性能、shader 整合。**

### 必须交付的文件

| 文件 | 内容 | 验收 |
|---|---|---|
| `src/lib/sky/SkyScene.ts` | renderer 单例 + Scene + Camera；三态状态机(GROW/AMBIENT/IDLE)；整合星点/星座线/月亮/地面/城市/人物；视差阻尼 | draw calls ≤10 |
| `src/lib/sky/shaders/grow.vert` | 建筑生长+替换 shader（你二次稿第五节版本） | GPU 化 |
| `src/lib/sky/renderer.ts` | renderer 初始化、画质分级 high/mid/low、context lost 恢复、setPixelRatio | 竖屏地平线65% |
| `src/lib/sky/perf.ts` | 10 行 `?perf=1` 采样器，测完可删 | 不进主包 |

### 接口契约
- 给 CELESTIAL：星点/连线 shader buffer 布局
- 给 URBAN：`compileCity` 输出的 CityBuffer 直接进 shader
- 给 IMMERSIVE：`onStateChange(GROW/AMBIENT/IDLE)`、`cameraApi.parallax(dx,dy)`、`setHorizonRatio()`、`captureFrame()`（toBlob 同帧）

### 关键纪律
- 旧 `SkyCanvas.tsx`（Canvas2D）从 `/sky` 模块图断开 import，不进 chunk
- `astro.ts` 是唯一复用的旧文件
- `three@latest` + lockfile 提交
- WebGL2 only，WebGL2 不可用降级到 CSS 静态页

### 不许做
- 不写天文算法（CELESTIAL）
- 不写城市数据（URBAN）
- 不写 UI 面板（IMMERSIVE）
