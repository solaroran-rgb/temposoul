## 0. 本规范存在的理由（先读这一节）

`visual-anchor-jinan-v2.md` 已经列了参数。为什么还需要本规范？

因为它列的是**平铺的参数表**，不是**设计系统**。平铺参数表的致命缺陷：

| 缺陷 | 后果 | 本规范的解法 |
|---|---|---|
| 没有层级关系 | 山体 3.6px / 地标 2.6px / 建筑 1.6px——但**谁是主角**？改一处就失衡 | §3.1 建立六级亮度层级序列，一切宽度/亮度由层级推导 |
| 没有使用规则 | 「暖橙仅局部」——多局部算局部？多亮算亮？ | §3.2 给出**面积占比硬上限**与可判定阈值 |
| 没有构图约束 | 相机移一下，"人在宇宙中渺小"就没了，但没有任何数值阻止它 | §4 给出**人形占屏比上下限**、地平线位置、负空间配额 |
| 没有容差 | 对拍时"差一点"算不算过？靠感觉吵 | §8 给出**每个维度的 P0/P1/P2 判定阈值** |
| 没有根因映射 | 改完发现画面糊了，不知道是线的宽度、透明度还是混合模式 | §7 给出**症状 → 根因 → 参数**对照表 |

**本规范的目标**：让一个没有审美直觉的执行者，按表执行也能做到 70 分；让有审美直觉的执行者，知道每一步该动哪个旋钮。

## 1. 视觉北极星（North Star）—— 唯一裁判

一句话：

> **这不是"数据可视化"，这是一张「人在宇宙中渺小」的**数字哲学海报**；数据只是它的颜料，不是它的目的。**

三条不可让步的美学公理（任何改动若违反其中一条，无论技术多正确都是**失败**）：

| # | 公理 | 可判定表述 |
|---|---|---|
| **A1** | **黑是主角，光是客人** | 全画纯黑（#000000）占比 ≥ **62%**；任一 64×64 像素块的**平均亮度**不得超过 L*45（约 `#737373`）。发光元素是撒在黑夜里的，不是把黑夜照亮。 |
| **A2** | **层级分明，无平铺** | 画面必须能一眼读出「星空 > 地貌 > 城市 > 人物 > 细节」五级层次。任意两级的峰值亮度差 ≥ 25%。**禁止所有元素同一亮度平铺**（当前实现最大病症）。 |
| **A3** | **克制高于丰富** | 每个新增视觉元素，必须先移除或压暗一处已有元素。**净视觉复杂度不得增加**。宁可少一层，不可多一根线。 |

**A2 是最重要的一条。** 当前 `p1b` 版本的死因就是 A2：整个地面区以同一亮度（`uColorCore` #00E5FF）平铺渲染，山、建筑、水系、植被亮度全等，于是画面读起来是"一坨青蓝色的东西"，而不是"一片沉睡的大地托着城市"。

## 2. 色彩规范（B1 层）

### 2.1 色板（单源：`src/theme/holographic-tokens.ts`）

**规范要求：本节即 token 文件的规范形态。§5 会给出对 token 文件的补齐建议（新增 4 个压暗档位键），补齐前用 §5 的等效写法。**

| 语义 | Token 键 | 值 | 用途（唯一） |
|---|---|---|---|
| 虚空底 | `bg-void` | `#000000` | scene clear color |
| 网格暗 | `grid-dark` | `rgba(0,229,255,0.08)` | 地面栅格 |
| 青蓝核心 | `cyan-core` | `#00E5FF` | **仅限 L2 层级**：地标棱线、星点、城市主轮廓峰值 |
| 青蓝光晕 | `cyan-glow` | `rgba(0,229,255,0.35)` | 线条外层光晕 |
| 青蓝暗 | `cyan-dim` | `#008B99` | **L3/L4 层级**：水系、道路、远山、网格 |
| 星座线 | `cyan-constellation` | `rgba(77,208,225,0.40)` | 星座连线（alpha 已含） |
| 文本亮 | `text-bright` | `#FFFFFF` | 主标题、地名标注 |
| 文本暗 | `text-dim` | `rgba(255,255,255,0.60)` | 副标题、坐标、HUD 数值 |
| 暖橙 | `accent-warm` | `#FF8C00` | **仅限单一焦点**（见 §3.2） |

> ⚠️ **规范裁定**：`holographic-tokens.ts` 中 `font-mono` 不是颜色，放在色彩 token 文件里可以，但**不得**被当作颜色解析（`renderTokens.parseTokenString` 会抛错，当前无风险，但需在文件头注释标明）。

### 2.2 面积配额（硬约束，可测量）

| 色彩族 | 全画面积占比 | 测量方式 |
|---|---|---|
| 纯黑 `#000000` | **≥ 62%** | 像素亮度 < L*8 的占比 |
| 青蓝族（core+glow+dim+constellation 合计） | ≤ 30% | 饱和度 > 0.2 且色相 175°–200° 的占比 |
| 白/近白（text-bright + 星点核心） | ≤ 7% | 亮度 > L*85 的占比 |
| **暖橙** | **≤ 0.8%，且必须聚成一簇** | 色相 15°–45° 的占比 |

**暖橙配额的历史教训**：`geoEngine.ts` 曾在 101 塔尖 **+塔身** 打两个焦点（`pWarm.push` 两次，size 6.0）。这在基准图里是不成立的——基准图**整个画面只有一处**暖色微光。**规定：全画暖橙焦点数量 = 1**（多点时必须视觉上聚合为单簇，簇内最远点距离 < 3% 画宽）。

### 2.3 禁止项（引用用户提示词原文的硬禁令）

- ❌ 大面积暖色 / 杂色 / 紫红 / 绿
- ❌ 任何写实照片、3D 实体渲染、立体曲面
- ❌ 实体填充面（**唯一例外**：粒子聚合形成的视觉密度，不得使用不透明面片）
- ❌ 阴影 / 外部光源 / 明暗立体光影
- ❌ 卡通 / 手绘 / 油画 / 水彩质感
- ❌ 模糊、低清晰度、噪点脏乱
- ❌ 文字扭曲乱码、水印、LOGO、边框画框、设备样机

## 3. 亮度层级与光效体系（本规范核心 · 一切参数的推导源）

### 3.1 六级亮度层级（L1 最亮 → L6 最暗）

**这是全规范最重要的一张表。** 所有线条宽度、透明度、颜色选择，都必须从这张表推导，不得单独指定。

| 层级 | 名称 | 视觉角色 | 峰值 alpha 目标 | 线宽 core（px） | 光晕半径（px） | 颜色 | 对应现有对象 |
|---|---|---|---|---|---|---|---|
| **L1** | 焦点 | 全画唯一视觉锚点 | 1.00 | — | — | `accent-warm` | 101 塔尖**单点**（粒子，size 6.0） |
| **L2** | 主体 | 观者目光首先落在的实体 | 0.72 | 2.4 | 6.0 | `cyan-core` | 地标棱线 / 塔身轮廓 |
| **L3** | 次体 | 主体周围的城市肌理 | 0.42 | 1.5 | 3.6 | `cyan-core` × 0.72 | 城市建筑轮廓（近/中） |
| **L4** | 环境 | 大地骨架，托住城市 | 0.26 | 1.2 | 3.0 | `cyan-dim` → 提亮版 | 山脊等高线 / 水系主线 |
| **L5** | 纹理 | 大地的呼吸，几乎不抢戏 | 0.14 | 0.9 | 2.2 | `cyan-dim` × 0.65 | 道路 / 地表扭曲线 / 远山 |
| **L6** | 星尘 | 氛围，感知得到但看不清 | 0.07 | 0.6 | 1.4 | `grid-dark` 级 | 地面栅格 / 浮尘 / 极远细碎 |

**层间硬约束**：相邻层峰值 alpha 比 ≈ **1.7×**（0.07→0.14→0.26→0.42→0.72→1.00 的近似几何级数）。连续三层不得为同一 alpha。

### 3.2 为什么必须是几何级数（推导，不是拍脑袋）

人眼在纯黑底上的亮度辨别阈值（Weber 分数）约 12–18%。所以：

- 层间亮度差若 < 1.3×，肉眼**无法区分**，画面读起来是"平的"——这就是当前 p1b 的病。
- 层间亮度差若 > 2.5×，中间层会**断层**，读起来像"主体浮在空中没有过渡"。
- **1.7× 落在可辨（>1.3）与连续（<2.5）的交集**，且六级连乘恰好覆盖 0.07→1.00 全动态范围（0.07 × 1.7⁵ ≈ 0.99 ✓）。

**推论**：任何一层调亮/调暗超过一档，必须同步检查相邻层，否则层级序列断裂。

### 3.3 光晕（glow）规范

线条不是"画一根线"，是"一根线 + 一圈光晕"。二者必须同时存在才成立。

| 参数 | 规范值 | 当前实现 | 判定 |
|---|---|---|---|
| `glowRadiusPx / coreWidthPx` | **2.2 – 2.6** | L2：8.0/3.6=2.22 ✓｜默认：4.0/1.6=2.5 ✓ | ✅ 结构正确 |
| `uCoreRatio`（核心占半宽比） | 0.28 – 0.34 | L2：1.8/5.4=0.33 ✓ | ✅ |
| `uCoreAlpha : uGlowAlpha` | **2.6 : 1** | 0.9 : 0.32 = 2.8 | 🟡 略偏高，建议 0.9:0.35 |
| 光晕衰减曲线 | `exp(-x²·k)`，k = **5.0** | `exp(-x*x*5.0)` ✓ | ✅ 保留 |
| 混合模式 | `AdditiveBlending` 全层 | ✓ | ✅ |
| `depthWrite` | 全层 `false` | ✓ | ✅ |

**关键裁定：光晕是"呼吸"的来源，不是"亮度"的来源。** 想让某个对象更亮，**先调 `uCoreAlpha`，不要调 `glowRadiusPx`**——加大光晕半径会让画面糊，而不是更亮。当前 `p1b` 画面"糊成一团"的高度嫌疑就在于此（见 §7 症状 S2）。

### 3.4 发光强度曲线（呼吸动效）

| 对象 | 周期 | 幅度 | 基准 |
|---|---|---|---|
| 观测者剪影粒子 | 4.5s | ±24%（0.5 ± 0.12） | 当前 `SkyScene.ts:512` 用 `sin(t*1.4)` ≈ 4.5s ✓ |
| 星点闪烁 | — | ±10%（`twinkleAmp` 0.10） | ✓ 保留 |
| 星云团块呼吸 | 18s | ±15% | 当前 `sin(t*0.35)` ≈ 18s ✓ |
| **禁止**：任何 < 2s 周期的闪烁 | — | — | 用户明确否决"游戏化动效" |

### 3.5 星点分层（L2/L6 混合层级）

| 参数 | 规范值 | 说明 |
|---|---|---|
| 星等阈值 | `uMagLimit` 6.0 | 保留 |
| 星点大小 | 按星等**非线性**映射，最亮 : 最暗 ≥ **3.5 : 1** | 当前无独立曝光，需检查 |
| 星点颜色 | 白 `#FFFFFF`（亮星）→ 青白（中）→ `cyan-dim`（暗星） | 按 BV 色温 + 星等双因子 |
| 衍射星芒 | 仅最亮 **≤ 12 颗** 有 | `diffractionMax` high=20 建议降至 **12** |
| 地平线淡出 | `smoothstep(-0.015, 0.02, y/500)` | ✓ 保留（消除遮挡盘） |

## 4. 构图与负空间规范

### 4.1 三大分区（硬比例）

以 2048×1152（16:9）为基准视口，竖直方向三分：

| 分区 | 画高占比 | 内容 | 亮度目标 |
|---|---|---|---|
| **星空区** | **0% – 58%** | 星点、星座、月亮、星云 | 大面积近黑 + 稀疏亮点 |
| **交界带** | **58% – 66%** | 星云枝杈 + 远山天际线 | **全画最暗横带**（刻意压暗，制造"地平线沉下去"） |
| **地貌区** | **66% – 100%** | 山脊、城市、水系、植被、人物 | 亮度自下而上递减 |

**交界带必须比地貌区更暗**——这是基准图高级感的关键之一：远处沉入黑，近处才有重量。当前 p1b 的地平线处是一条**最亮的横带**，方向完全相反。

### 4.2 水平构图（对称 + 焦点偏移）

| 要素 | 规范位置 | 容差 |
|---|---|---|
| 观测者人形 | 水平 **中心 ±1%** | ±2% |
| 主要地标（101） | 人形**正后方偏左 0–4%** | ±6% |
| 地标标注文字 | 人形正下方，间距 = 1.2 倍人形高 | — |
| 月亮 | 右上或左上象限，**不得与人形同轴** | — |
| 星座 | 星空区上半部，**避开中心 30% 宽的中轴带** | — |

### 4.3 视觉焦点唯一律（A3 的量化表达）

**全画在同一时刻只能有 1 个亮度 > L*70 的聚集区。** 允许的例外：星点（面积 < 0.3% 的离散点）。

判定方法：把画面分成 8×8 网格，计算每格平均亮度，**超过 L*70 的格子数必须 ≤ 2 且相邻**。

### 4.4 负空间节奏（留白配额）

| 区域 | 负空间（纯黑）配额 |
|---|---|
| 星空区 | ≥ 88% |
| 地貌区 | ≥ 55%（**这是"大地沉在黑暗里"的来源**） |
| 全画 | ≥ 62%（= §2.2 的纯黑占比） |

**推论（重要）**：地貌区 ≥55% 纯黑，意味着**地貌区所有发光元素的总面积必须 ≤ 45%**。当前 p1b 的地貌区发光面积目测 > 75%，这是"信息密集堆叠"的直接来源。

### 4.5 人形尺度（"渺小"的量化）

| 参数 | 规范值 | 当前实现 | 判定 |
|---|---|---|---|
| 人形高度 / 画高 | **6.7%**（≈1/15） | `group.scale = 4.0` × 人高 9.3 units。屏占比待实测 | ⚠️ 需实测校准 |
| 人形宽度 / 画宽 | ≤ 1.5% | — | ⚠️ |
| 光晕半径 / 人形高 | 1.3 – 1.6× | `halo.scale(42,58)` / 人高(9.3×4=37.2) = 1.56 ✓ | ✅ |
| 人形亮度 | 峰值 `text-bright`，但**面积 ≤ 0.4%** | 用 `LineLoop` + 210 粒子 | ⚠️ 轮廓线过亮过硬 |

> **当前最严重的单点问题**：`buildSilhouette()` 用 **正面站姿闭合轮廓**（`SkyScene.ts:231-245`），且 `scale 4.0`。基准图的人形是**背对镜头**的粒子弥散剪影，**没有清晰的肩线/手臂闭合线**。当前实现外轮廓是一条连续白线，因此在小尺寸下**读起来就是"一根白色立柱"**——这正是用户看到的。
> 见 §7 症状 S4 与 §6 修复指令 R4。

### 4.6 相机契约（构图锁定）

```
基准契约：camera.position (0, 58, 200) → lookAt (0, 20, -160)，fov 58°
视差上限：x ±6 units，y ±4 units（当前 SkyScene.ts:508-510 ✓ 合规）
```

⚠️ **历史冲突警告**：`docs/sky/HANDOVER.md` 记录了另一套已废弃契约 `(0,34,-95) → (0,18,120)`。**以本规范 + `visual-anchor-jinan-v2.md` 的 `(0,58,200)` 为准。** 两套契约不得混用，任何相机改动必须在 §9 记录并注明依据。

## 5. 字体排印与 HUD 规范

### 5.1 字体族

| 用途 | 字体族 | 理由 |
|---|---|---|
| 中文主标题 / 地名 | `"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif` | 基准图中文为**无衬线、细体、低字重** |
| 拉丁文 / 数值 | `"Space Grotesk", "Inter", system-ui, sans-serif` | 几何无衬线，与线稿语言同族 |
| 等宽（坐标 / 参数） | `"JetBrains Mono", "Courier New", monospace` | HUD 数值质感 |

> ⚠️ **当前实现问题**：`SkyScene.ts:141` 星座副标签用 `"Courier New", monospace` 22px 绘制，且**主标签中文之后紧跟同一行的英文大写**——两者在 sprite 里位置靠计算偏移（`84 + 50 * Math.max(2, zh.length)`），**中文长度一变英文就重叠**。这是截图中文字乱码叠影的直接原因。见 §7 症状 S6。

### 5.2 字号层级（以 1920×1080 视口为基准）

| 层级 | 元素 | 字号 | 字距 | 字重 | 颜色 |
|---|---|---|---|---|---|
| T1 | 品牌主标 `命律 TempoSoul` | **28px** | 0.18em | 300 | `text-bright` |
| T2 | 地名标注（人形下方） | **20px** | 0.32em | 300 | `text-bright` @0.96 |
| T3 | 面板标题（如 `观测数据`） | **12px** | 0.30em | 400 | `cyan-core` |
| T4 | 面板数值 | **13px** | 0.05em | 400 | `text-dim` → 值用 `cyan-core` |
| T5 | 角标 / 版本 / 坐标 | **9px** | 0.22em | 300 | `cyan-dim` @0.55 |

**字号硬约束**：任意两相邻层级的字号比 ≥ **1.25×**。当前 `SkyPage.tsx` 中 T2 地名用 `17px`、T1 主标用 `18px`——**比值为 1.06，肉眼不可分**，画面因此失去层级。见 §7 症状 S7。

**等宽字体禁令**：T1/T2 级**禁止**使用 monospace（当前 `SkyPage.tsx:251` 地名容器用 `fontFamily: 'monospace'`，与 `.sky-root` 的 Inter 设定冲突，实际渲染取决于浏览器回退）。地名的气质必须是"刻在虚空里"，不是"终端输出"。

## 6. 逐层差异裁决表（基准图 → 当前实现 → 修复指令）

**这是可直接执行的整改清单。** 每条含：现象 → 根因（代码定位）→ 修复指令 → 验收判据。

### R1 · 建筑"实心化"【P0 · 最高优先】

| 项 | 内容 |
|---|---|
| **现象** | 城市区域糊成一整块高饱和青蓝色实心团，读不出建筑轮廓 |
| **根因** | ① `glowLine.ts` FRAG 中 `glow = exp(-x*x*5.0)` 在宽光晕（8px）下叠加；② L2/L3 全用 `cyan-core` + `AdditiveBlending`；③ `applySegDrawRange` 按 `cityRatio` 截断，但**几何段密度未随距离稀释**——近处建筑密集 → 光晕互相叠加 → 加法混合下必然过曝 |
| **修复指令** | ① 建筑轮廓按 §3.1 归 **L3**：`uCoreAlpha` 0.42、`glowRadiusPx` 3.6、`coreWidthPx` 1.5；② 城市五对象的 base 颜色从 `uColorCore` 改为**按距离分级的 dim 混色**（近 `cyan-core`×0.72，远 `cyan-dim`）；③ `CITY_LAYER` 值域按 §3.1 重设（见 §8 数值表） |
| **验收** | 城市区可数出 ≥ 15 栋独立建筑轮廓；该区域 64×64 块平均亮度 ≤ L*45 |

### R2 · 地平线过亮（方向相反）【P0】

| 项 | 内容 |
|---|---|
| **现象** | 地平线处是一条最亮的横带，远山/远景反而最亮 |
| **根因** | `geoEngine.ts:353` 山体 `y = level * S * 2.0` 抬升 2 倍，且 `buildTerrainPayload` 的 `bands` 三条都给了**高 layer 值**（1.0/0.92/0.78）——远山与近山亮度几乎相同，违反 A2 |
| **修复指令** | ① 三条 band 的 layer 改为 **0.42 / 0.28 / 0.15**（远暗近亮，且全部落在 L4–L5）；② 山头颜色由 `uColorCore` 改为 `uColorDim`；③ 维持 `y < 14` 的 z 过滤（不要动，那是防遮挡的正确修复） |
| **验收** | 交界带（58%–66% 高）平均亮度 **低于** 地貌区（66%–100%）平均亮度 |

### R3 · 星云贴片感【P1】

| 项 | 内容 |
|---|---|
| **现象** | 星云是边界生硬的蓝色椭圆色块，像贴上去的 |
| **根因** | `NebulaOverlay.tsx:57-64` 用 `createRadialGradient` + `ellipse` 直接填充，**无噪声调制**；16 个 blob 的 alpha 0.10–0.26 在 `lighter` 缺省混合下累积出硬边 |
| **修复指令** | ① 每个 blob 填充前叠一层**分形噪声遮罩**（可在离屏 canvas 预生成一张 512×512 的 value-noise，按 blob 区域采样 alpha）；② blob 数量 16 → **9**（A3 减法）；③ alpha 上限 0.26 → **0.15**；④ 加 `ctx.filter = 'blur(40px)'` 于 blob 层（性能可控，仅 55% 高度） |
| **验收** | 星云边缘的 alpha 梯度跨度 ≥ 画面宽度的 12%（即无 < 2% 宽度的硬边） |

### R4 · 人形"白柱化"【P0】

| 项 | 内容 |
|---|---|
| **现象** | 人形读起来是一根白色立柱，看不出人 |
| **根因** | `SkyScene.ts:229-295`：① 用**正面站姿闭合轮廓** `LineLoop`（连续白线），不是粒子弥散；② `scale 4.0` 放大后轮廓线宽不变，视觉上变成"细高白框"；③ 光晕 `halo.scale(42,58)` 是**垂直拉长**的椭圆（42 宽 / 58 高），强化了"柱状"感 |
| **修复指令** | ① **删除 `LineLoop` 外轮廓**（基准图人形无清晰外轮廓）；② 粒子数 210 → **900**，采样范围略大于轮廓（弥散 `×1.15`），并用 `size 0.9` + 低 opacity 分层（核心密、边缘疏，密度按到轴心距离 `1/d` 衰减）；③ 光晕改**圆形**（`scale(46,46)`），opacity 0.22 → **0.16**；④ 人形总高屏占比按 §4.5 = 6.7%，需实测反推 `scale`；⑤ 粒子颜色从 `0xf2fbff` 改为 **`cyan-core` 混 `text-bright`**（基准图人形是青白，不是纯白） |
| **验收** | 人形高/画高 = 6.7% ± 1.5%；轮廓无连续直线段；人形区平均亮度 ≤ L*55（不得成为最亮区） |

### R5 · 水系/道路不可见【P1】

| 项 | 内容 |
|---|---|
| **修复指令** | 水系归 **L4**（`uCoreAlpha` 0.26，`coreWidthPx` 1.2，色 `cyan-dim`）；道路归 **L5**（0.14 / 0.9px）。**注意 `cyan-dim` = #008B99 本身已很暗**，在 Additive 下几乎不可见——需按 §3.1 用「`cyan-dim` × 1.35 提亮」的等效色（≈ #00BCCF），不能直接改 token（`cyan-dim` 还被网格复用） |
| **验收** | 水系线条在桌面全图缩略图下可辨识 → 判据：水系区域与其相邻地表的亮度差 ≥ L*6 |

### R6 · 负空间不足【P0 · 结构性问题】

| 项 | 内容 |
|---|---|
| **现象** | 画面被塞满，无呼吸感 |
| **根因** | 多重叠加：地面栅格（`grid` layer 0.32 + 0.9 地平线带）本身占满下半屏 + 城市 + 地貌 + 植被 + 星云，五层全在同一亮度域 |
| **修复指令** | ① 地面栅格 layer：`grid` 0.32 → **0.07**（L6），`horizon` 0.9 → **0.14**；② 栅格间距 10 → **20 units**（线数减半）；③ 尘埃 320 → **160**；④ 植被粒子 2.2 size → **1.4** 且 opacity ≤ 0.2 |
| **验收** | §4.4 负空间配额全部达标（星空 ≥88% / 地貌 ≥55% / 全画 ≥62%） |

### R7 · 文字叠影 / 乱码【P1】

| 项 | 内容 |
|---|---|
| **根因** | `SkyScene.ts:144` 英文副标签 x 坐标用 `84 + 50 * Math.max(2, zh.length)` **手算偏移**，中文长度变化即重叠；且 sprite 宽 820px 固定，长名会被裁 |
| **修复指令** | ① 改成**两行独立绘制**（中文 y=44，英文 y=88），不再横向拼接；② sprite 宽度按 `measureText` 实测 + padding（当前硬编码 820 改为 `max(280, 中文宽 + 英文宽 + 60)`）；③ 若 P1 范围要收敛，可**直接去掉英文副标签**（基准图只有中文标签）——**推荐此项**，符合 A3 |
| **验收** | 双视口下 14 个星座标签无字符重叠、无裁切 |

## 7. 症状 → 根因 → 参数 对照表（排障用）

| 症状 | 最可能的根因（按概率降序） | 该动的参数 | 不该动的参数 |
|---|---|---|---|
| **画面糊成一团** | ① 光晕半径过大 → 相邻线段光晕叠加；② Additive 下过曝；③ 段密度过高 | `glowRadiusPx` ↓、`uCoreAlpha` ↓、段密度 ↓ | ❌ 不要靠降 `uOpacity` 整体压暗（会同时失去核心锐度） |
| **画面太平、没层次** | 多层同一 alpha | 按 §3.1 重排层级，拉开 1.7× 比值 | ❌ 不要靠加元素"制造丰富" |
| **太亮 / 刺眼** | ① 大面积使用 `cyan-core`；② 暖橙超配额；③ 星点衍射过多 | 换 `cyan-dim` 系、暖橙减到 1 点、`diffractionMax` ↓ | ❌ 不要直接把 `glowAlpha` 归零（会失去全息感） |
| **看不清细节** | ① 近处过曝把细节吃掉；② 光晕盖住核心 | `uCoreRatio` ↑（核心占比大）、`glowRadiusPx` ↓ | ❌ 不要加描边（违反禁实体填充） |
| **整体偏灰、不"深邃"** | ① 底色不是纯黑；② 雾把黑吃成灰；③ 星云弥散污染大面积 | 检查 `clearColor` = #000000、`FogExp2` 密度、星云 alpha | ❌ 不要加暗角作弊 |
| **人物看不出是人** | 外轮廓线存在 / 尺寸过大 / 光晕垂直拉长 | 见 R4 | ❌ 不要"把线画粗" |
| **星空不像真实天空** | 星等映射线性 / 衍射滥用 / 无地平线淡出 | `uMagLimit`、星点大小非线性映射 | ❌ 不要随机增删星点 |
