等价：y(ref-c)% = 1.355 × y(CT-1)% − 35.5%
反解：CT-1 下半部 = ref-c 下半部 × 0.7380（压缩到 73.8%）

前三个独立批次（440 LED 点阵墙 / 480 青色栅栏 / 490 竖柱阵）全部被判定为「不达标」，而判定所用的数字，是拿 CT-1（68–69%） 当靶子算的。真实目标（ref-c，老板参考图）在 56–58%。

而且判决方向是反的。 以 480 批的带区为例：

表现优先级（严格按老板 V1.0 §7 权重表）：整体构图 ★5 > 光线氛围 ★5 > 城市轮廓 ★4 > 真实数据 ★4 > 建筑细节 ★2 > 真实 3D ★1。

6.8 ⑧ 俯视城市肌理 · 路网街区（33.6%）

视觉目标：地图 × 星图 × 建筑线稿 × 粒子艺术。不是 Google Maps × 3D 游戏。

6.9 ⑨ 前景 · 人影与地光（2.8%）

人物是页面的情绪核心，但：

  • 不是具体的人、不是真实照片、不是写实 3D 人物 → 是「一个正在面对宇宙的人」。
  • 位置：画面底部中央附近；身体不需完整（背影 / 肩 / 头 / 上半身）。
  • 表现：半透明深色剪影 + 青蓝色粒子边缘；轮廓不能太亮。
  • 暗剪影 + 亮背景：人形是相对更暗的形体，被背后辉光托出。禁止渲染成「一根亮白立柱」（v1 R4 历史事故）。
  • 禁止：写实脸 / 衣服细节 / 摄影感 / 超级英雄感 / 游戏角色感。

前景环境代表「人的现实世界」，语义链：宇宙 = 无限；城市 = 现实；人物 = 我；前景 = 我所处的人生环境。表现用几何线条、曲折结构、粒子、微弱荧光、不完整轮廓 —— 形成「复杂、曲折、但仍可向前走」的空间。

14. 「数据真实，表现艺术化」的代码约束

原则（老板 V1.0 §18）：允许非线性视觉映射；不能把虚假的建筑说成真实建筑。

14.1 强制字段

每一个图元（建筑 / 道路 / 河流 / 山脊 / 地标）必须携带 source 字段。

{
  "id": "b_1042",
  "kind": "building",
  "source": "osm:way/123456789",     // 真实来源；合成数据则为 "synth:roadside/v1"
  "h_real_m": 60.0,                  // 真实高度（米）—— 永不改写
  "h_visual": 138.0,                 // 视觉高度（单位）—— 可非线性映射
  "lat": 29.7271, "lon": 120.2345,
  "footprint": [[...]],
  "synth": false
}

14.2 三条硬规则

#规则
1h_real_m / lat / lon / footprint 只能来自数据源，禁止在任何渲染阶段被改写或估算
2视觉映射（h_real_m → h_visual）必须是单一、可审计、全局一致的函数，不得逐栋随机
3合成图元（synth: true）必须在图层中可区分，且合成规则必须可复现（固定种子）；不得用合成数据冒充实测数据

14.3 推荐视觉高度映射

h_visual = clamp( pow(h_real_m, 0.35) * k , h_min , h_max )
  • 幂压缩：保留高度排序关系（高的仍更高），同时压缩量级差。
  • k / h_min / h_max 为全局常量，写在本文件，改动需记变更记录。
  • 禁止：给一栋实测 60m 的楼渲染出数值上等同 300m 楼的高度（那等于伪造城市事实）。允许的是「让 60m 的楼在画面里更有轮廓存在感」—— 即增强轮廓与辉光，不虚构楼体高度数值、数量与位置。
